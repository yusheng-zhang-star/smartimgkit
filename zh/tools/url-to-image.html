这个页面真正能截的东西：同源页面

代码里只有一句 html2canvas(previewFrame.contentDocument.body)。要拿到 contentDocument，前提是 iframe 里的页面和本站同源。也就是说，你自己部署在 smartimgkit.com 上的页面能截，别人的站点一律不行。这一点决定了它的用途只有一类：给自己站里的页面做留档图。

最常见的用法是改版对比。改完首页样式，把线上页面截一张存下来，下周再截一张，两张并排放，颜色、间距、按钮位置的差别一眼就能看出来，比来回切换浏览器标签页对比快得多。做设计的同事提验收意见时，也习惯直接在截图上圈。

第二个用法是给教程配图。写工具使用说明需要展示操作界面，页面截图比手绘示意图准确，读者照着截图找按钮不会找错。同源页面截出来的图没有水印、没有遮挡，也不用担心字体缺失导致排版错位。

第三个用法是发给不看链接的人。微信群里发一条链接，多数人不会点；发一张页面截图，对方一眼就知道你在说什么。做社群推广、写公众号互推文案时，一张完整的页面图比干巴巴的链接有效。

这三个场景有个共同点：截的都是自己可控的页面。只要目标站点不在 smartimgkit.com 域名下，这个工具就帮不上忙，往下看原因。

截淘宝、拼多多、公众号为什么一定失败

把外部网址填进去点「开始截图」，iframe 会正常显示出页面，看起来一切正常，但点下载按钮时什么都不会发生。原因在浏览器内核：跨域 iframe 的 contentDocument 属性返回 null，html2canvas 收到 null 直接抛错，这段代码没有写 try/catch，也没有错误提示，所以表现就是「点了没反应」。按 F12 打开控制台，能看到一条 SecurityError 或者读取 null 属性失败的报错。

第二层拦截是 X-Frame-Options 和 CSP 的 frame-ancestors。淘宝、京东、绝大多数银行和政务站点都发这个响应头，禁止自己的页面被别的站点套进 iframe。遇到这种站点，连预览框里都是白的，压根走不到截图那一步。

第三层是画布污染。就算页面能嵌、能读，里面淘宝的商品主图、字体文件、统计脚本都来自别的域名。html2canvas 把这些图片画进 canvas 之后，canvas 就被标记为被污染，再调用 toDataURL 导出会直接抛安全错误。所以「跨域页面也能截」这个说法在纯前端方案里站不住脚。

真需要截外部网页，用现成的工具更省事：Chrome 或 Edge 装 GoFullPage 这类整页截图扩展；或者按 F12 打开开发者工具，Ctrl+Shift+P 输入 Capture full size screenshot，浏览器会自己滚动拼接整页。手机上直接系统截图，长图用手机自带的滚动截屏。

还有一点容易被忽略：这一页虽然不上传你的网址，但 iframe 是从你自己的浏览器直接向目标站点发起请求的，对方服务器的访问日志里会出现你的 IP 和这次访问。想让访问痕迹完全不存在，只能用离线工具。

需要拿网页当证据时，别用截图

运营、法务、审计经常要存证：发现同行虚假宣传、记录促销前后的价格、留一份活动页面的原始样子。截图能说明「当时长这样」，但证明力有限——图片可以修，也没有时间戳和来源。更稳的做法是浏览器打印：Ctrl+P 目标选「另存为 PDF」，得到的是带文字层的 PDF，能搜索、能复制，页面地址和打印时间也在文件属性里。

如果一定要图，记得把地址栏一起截进去。纯页面截图看不出是哪个网址，对方完全可以质疑来源。系统截图工具（Win+Shift+S、macOS 的 Shift+Cmd+4）都能连浏览器界面一起框进去，这一步这个网页转图片工具做不到，它只认 iframe 里的 DOM。

做竞品分析、素材收集的场景也类似：与其一张张截，不如把链接丢进笔记工具让它们自动抓摘要，或者用浏览器书签加标签管理。截图存多了找不到、占空间、还会因为压缩变得看不清，检索成本比收藏链接高得多。

最后提醒一句版权。截别人的页面做学习参考没问题，公开发布、商用、当自己的内容发，都可能构成侵权。要引用就截局部、注明来源，别整页搬。
