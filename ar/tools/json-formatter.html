🔧 تنسيق JSON

نسّق JSON وجمّله وضغطه وتحقق من صحته داخل المتصفح — الصق فقط وستظهر النتيجة.

الصق نص JSON واختر التنسيق بمسافتين أو أربع، أو اضغطه سطرًا واحدًا، أو تحقق من صحته فقط. التحليل يتم عبر JSON.parse الأصلية في المتصفح فالسلوك مطابق للمعيار — وعند الخطأ يظهر لك رسالة تحدّد موقعه.

  • أربع عملياتتنسيق بمسافتين، تنسيق بأربع مسافات، ضغط سطر واحد، تحقق من الصحة
  • المحركJSON.parse وJSON.stringify الأصليتان — مطابقة لمعيار ECMA-404
  • تشخيص الخطأرسالة V8 الأصلية تحدد نوع الخطأ وموضعه بالأحرف
  • الخصوصيةبياناتك لا تغادر تبويب المتصفح

📤 النتيجة

طريقة الاستخدام

1

الصق JSON

ضع السلسلة — من رد واجهة برمجية أو ملف إعدادات أو سجل — في مربع الإدخال. مضغوطة أو منسّقة، كلاهما مقبول.

2

اختر العملية

اضغط «تنسيق» لترتيب الأسطر بالمسافات، أو «ضغط» لدمجها سطرًا واحدًا، أو «تحقق» للفحص دون تعديل.

3

اقرأ الرسالة

عند وجود خطأ تظهر رسالة تحدد نوعه وموضعه بالأحرف — كنقطة انطلاق لتحديد المكان الذي تصلحه.

4

خذ النتيجة

انسخ JSON المعالج إلى محررك أو ملف الإعدادات.

شرح كل عملية

مسافتان أم أربع؟ اختر حسب معيار مشروعك

البيانات نفسها لكن بشكلين. المسافتان هي الافتراضية في JSON.stringify والشائعة في مشاريع جافاسكربت وNode، والأربع شائعة في التوثيق ومشاريع بايثون. القاعدة العملية: اتبع ما هو موجود فعلًا في ملفات المشروع — خلط نمطين في مستودع واحد ينتج فروقًا زائدة مزعجة عند مراجعة الكود جماعيًا.

الضغط — متى يفيد

الدمج في سطر واحد يقلّل الشكل عند إرسال JSON عبر الشبكة أو وضعه في متغير بيئة. انتبه: هذه إزالة مسافات وليست ضغطًا حقيقيًا مثل gzip — للسلاسل الكبيرة يبقى gzip أكفأ بكثير. استخدم الضغط حين تريد شكلًا نصيًا نظيفًا يقبل لصقه في مكان لا يحب الأسطر المتعددة.

التحقق وقراءة رسالة الخطأ

زر التحقق يشغّل JSON.parse دون الكتابة فوق نتيجتك. عند الخطأ تحصل على رسالة مثل «Unexpected token } in JSON at position 42» — الرقم 42 هو موضع الحرف في السلسلة التي لصقتها (يبدأ العدّ من صفر). حيلة مفيدة: نسّق السلسلة أولًا ثم تحقق، لأن موضع الخطأ في النسخة متعددة الأسطر يقترب من موضعه الحقيقي. حدود يجب معرفتها: JSON.parse يرفض الفاصلة الزائدة آخر المصفوفة، والتعليقات بـ //، والمفاتيح بدون علامات تنصيص — الثلاثة صالحة في جافاسكربت العادية لكنها غير صحيحة في معيار JSON.

حدود الحجم الواقعية

لا حد مفرض من الأداة، لكن تحليل سلاسل بعشرات الميجابايتات قد يبطئ التبويب ثوانٍ. لملفات الإعدادات وردود الواجهات وبيانات تحت بضعة ميجابايت، كل العمليات شبه فورية.

حالات استخدام

قراءة رد واجهة برمجية لمنصة توصيل

المطوّر الذي يربط متجره على سلة بواجهة شركة شحن يستلم JSON مضغوطًا في سطر واحد طويل. الصقه ونسّقه بمسافتين لتظهر بنية الحقول فيكتب التحليل بثقة.

فحص ملفات الإعدادات قبل النشر

ملف إعدادات نُسخ يدويًا وفاصلة زائدة واحدة تكفي لإسقاط النشر. تمريره على «تحقق» قبل كل رفع يستغرق ثوانٍ ويوفر ساعات تشخيص.

تجهيز بيانات تجريبية للعرض

تحتاج بيانات وهمية لعرض منتج للعميل: خذ نموذج JSON من توثيق الواجهة، نسّقه ليقرأه فريقك في مراجعة الكود.

الأسئلة الشائعة

نعم. الأداة تستخدم JSON.parse فتقبل JSON الصحيح فقط: مفاتيح بعلامات تنصيص، لا فاصلة زائدة، لا تعليقات. النسخ المكتوبة بأسلوب كائن جافاسكربت تحتاج تعديلًا قبلها.
لا. التحليل والتنسيق يجريان عبر JSON.parse وJSON.stringify داخل تبويبك، ولا يوجد أي طلب شبكة يحمل بياناتك.
لا حد مفرض؛ عمليًا ما دون بضعة ميجابايتات يُعالج فورًا. السلاسل الضخمة جدًا قد تبطئ التبويب ثوانٍ لكنها تعمل.
لا. النتيجة نص خام منسّق بالمسافات — كافٍ للقراءة والنسخ، لكن دون تلوين. الصقها في محرر يدعم التلوين مثل VS Code لتراها ملونة.
الرسالة تشير إلى موضع الحرف (position) في السلسلة لا رقم السطر. مع JSON المنسّق متعدد الأسطر استخدم الموضع للبحث في محرر يعرض رقم الحرف.
لا. التنسيق والضغط يغيّران المسافات وأسطر الجدولة فقط دون المساس بالمحتوى. الشرط الوحيد أن يكون JSON المدخل صحيحًا حتى تظهر نتيجة.
ليس في النسخة الحالية. الأداة تركز على التنسيق والضغط والتحقق. لتغيير البنية استخدم أدوات مثل jq بعد التنسيق هنا.
