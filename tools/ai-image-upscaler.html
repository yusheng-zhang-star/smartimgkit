Batch Image Upscaler

This tool enlarges an image 2x or 4x by redrawing it on a canvas at the browser's highest interpolation quality, then exporting a PNG. It is not a super-resolution model: it interpolates between the pixels that are already there, so a soft photo comes out larger and still soft. That makes it dependable for hitting a size threshold and useless for recovering detail that was never captured. Everything runs locally, with no model to download.

What resampling actually does to a pixel

The enlarging step is a single canvas call. The tool creates a canvas whose width and height are the original dimensions multiplied by the factor you picked, switches smoothing on, sets the smoothing quality to high, and draws the source image scaled up to fill it. Every output pixel is therefore a weighted average of the source pixels around it — a wider, smoother-weighted average than the browser would use at default quality, but still an average.

That single sentence explains both the strength and the limit. When you enlarge 2x, four output pixels share the information of one input pixel; at 4x, sixteen do. Edges that were one pixel wide become two or four pixels of gradient, which is why an enlarged image looks smooth rather than blocky. Nothing is added. A photo that was already soft, motion-blurred or compressed comes out larger, smoother and just as soft in the same proportion.

A super-resolution model behaves differently: it has learned what natural images look like and generates plausible fine detail, which is why it can make an out-of-focus portrait look convincing. The trade is that generated detail is invented rather than measured — small text can turn into invented letterforms and faces can drift. This page deliberately takes the conservative route: whatever is in your file stays exactly as measured, only bigger.

Situations where enlarging is genuinely the right fix

Print and marketplace rules are written in pixels, not in perceived sharpness, which is where an upscale earns its place:

  • Print at 300 dpi. A 4×6 inch print needs about 1200×1800 pixels; A4 needs roughly 2480×3508. A 600×900 original only needs 2x to clear the smaller of those, and the print will look correct at arm's length even though no new detail appeared.
  • Marketplace upload floors. Several large marketplaces ask for a long edge of at least 1000–1600 pixels before they enable zoom, and hand-made and print-on-demand platforms often want 2000. Enlarging a decent 1200-pixel product shot to 2400 satisfies the check without inventing anything misleading.
  • Screens and slide decks. A 1280×720 asset on a 1920×1080 projector shows visible pixel steps; a 2x pass removes the stepping and reads as intentional at viewing distance.
  • Mockups and placeholders. When a low-resolution image is going to sit inside a template at a fixed display size, enlarging it avoids soft-edged blocks in the layout.

Places where it will disappoint, and no amount of interpolation fixes: an out-of-focus shot, a photo with heavy JPEG blocking (each 8×8 block is enlarged along with everything else), a low-quality scan, and any case where a viewer will look for real texture at 100% zoom. For those, the honest options are a super-resolution model, a re-shoot, or a higher-resolution source file.

Batch behaviour, memory ceilings and output size

Files are handled one after another: each is read with FileReader, decoded through an Image object, drawn to a canvas, and exported with toDataURL('image/png'). There is no queue limit and no per-file progress bar — a batch of twenty finishes in order, and each finished thumbnail appears as its turn completes. Because the page holds the source images and their enlarged copies in memory at the same time, peak memory is roughly the sum of all canvases rather than the largest one.

Canvas size is the practical ceiling. Desktop Chrome refuses a canvas whose longest side exceeds 16384 pixels or whose total area passes roughly 268 megapixels; mobile Safari is stricter, and the limit varies with available memory rather than being a fixed number. A 4000×3000 photo at 4x becomes 16000×12000 — 192 megapixels, 768 MB of uncompressed pixel data before PNG encoding — which is exactly the case that fails on a phone. If a 4x run dies, drop to 2x or crop first.

Output is always lossless PNG, so file size tracks pixel count rather than visual complexity: a photographic 4000×3000 PNG is typically 8–15 MB, and the 4x version can pass 100 MB. If the destination is a website, convert the result to JPEG or WebP afterwards. The download keeps your original name with an upscaled- prefix.
