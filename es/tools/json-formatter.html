Cómo se usa

1

Pega tu JSON

Copia la respuesta de una API o el contenido de tu fichero .json en el cuadro de entrada.

2

Elige la acción

Formatear con sangría de 2 o 4 espacios, minificar para ahorrar bytes o validar sin cambiar nada.

3

Lee los errores con calma

Si el JSON no es válido, verás el mensaje del parser con la posición aproximada del problema.

4

Copia el resultado

El JSON formateado o minificado queda en el cuadro de salida; pulsa «Copiar» y pégalo donde lo necesites.

Guía detallada de uso

El formateo usa el parser JSON nativo del navegador: primero valida y después reescribe con la sangría que elijas. No interpreta el contenido, solo la estructura, así que claves y valores viajan intactos del cuadro de entrada al de salida.

Depura respuestas de API sin dolor

La respuesta en crudo de un endpoint llega en una sola línea imposible de leer. Pégala aquí, formatea con sangría de 2 espacios y verás de un vistazo qué campos devuelve, qué tipos tienen y dónde se esconde el dato que buscas.

Distingue comas de dos puntos a simple vista

Los errores de sintaxis más comunes —coma colgante, comilla simple, clave sin comillas— son fáciles de ver en el JSON sangrado. Si prefieres confirmación automática, «Validar» te dice si el parser acepta el texto sin tocarlo.

Minifica antes de guardar o enviar

Un JSON con sangría puede pesar el doble o el triple que el mismo contenido compactado. Minifícalo para ficheros de configuración, fixtures de pruebas o carga útil que viaja por la red, y recuperarás los espacios cuando quieras con un simple formateo.

Todo en local, sin pegarlo en servicios ajenos

El JSON se procesa en tu navegador: ideal para respuestas con datos de clientes, tokens o configuración interna que no deberías pegar en herramientas web de terceros.

Validar JSONs antes de mandarlos a la API

Los desarrolladores editan JSONs a mano, cuando arreglan un bug o prueban una respuesta. Pero es facil que se te olvide una coma o una llave, y la API responde con error de sintaxis. La solucion es validar el JSON antes de mandarlo.

Pega el JSON en esta herramienta, y la herramienta valida la sintaxis. Si hay un error, te avisa en que linea esta. Asi, arreglas el error antes de mandar el JSON a la API, y evitas que la peticion falle. Es el habito simple que evita horas de debugging.

  • JSON de configuracion: valida el JSON de configuracion antes de desplegar el sitio.
  • JSON de respuesta: valida el JSON de respuesta antes de mandarlo al cliente.
  • JSON de un webhook: valida el JSON del webhook antes de que el sistema lo procese.

Otro detalle: cuando valides un JSON antes de mandarlo a la API, revisa que no haya comas de mas al final de los objetos. Las comas de mas son el error mas comun cuando editas JSON a mano, y la API responde con error de sintaxis. La herramienta de validacion te avisa si hay una coma de mas, y la puedes arreglar antes de mandar el JSON.

Un detalle tecnico: el formateador usa el estandar JSON.parse y JSON.stringify, que son los mismos metodos que usan todos los navegadores. Si el JSON tiene un error de sintaxis, como una coma de mas al final de un objeto, el parser lo detecta y te muestra en que linea esta el error.
