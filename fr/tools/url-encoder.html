Encoder ou décoder une URL

1

Collez la chaîne

Collez l'URL complète ou seulement la valeur d'un paramètre, selon ce que vous voulez obtenir.

2

Choisissez le mode

Encodez un composant quand la chaîne est une valeur de paramètre. Encodez l'URL complète quand vous avez une adresse entière à nettoyer, sinon les / et ? deviennent %2F et %3F.

3

Encodez ou décodez

Le décodage sert à relire une URL reçue avec des %C3%A9 partout. L'encodage sert à construire une URL correcte à partir d'un texte lisible.

4

Vérifiez le résultat

Testez le lien obtenu dans un navigateur : une URL correctement encodée doit afficher la page attendue, sans caractère cassé.

Composant ou URL complète : la distinction qui compte

Encoder un composant échappe tous les caractères qui ont un sens particulier dans une URL : / ? : @ & = + $ , # . C'est le mode à utiliser pour une valeur de paramètre, par exemple un terme de recherche ou une adresse e-mail.

Encoder une URL complète laisse ces mêmes caractères intacts, puisque ce sont eux qui structurent l'adresse, et n'échappe que ce qui est réellement interdit : espaces, guillemets, accents, chevrons. Utiliser le premier mode sur une URL entière donne https%3A%2F%2Fexemple.fr, qui n'est plus une adresse.

Le piège est symétrique : encoder un composant avec le mode URL laisse passer une esperluette, qui coupe le paramètre en deux côté serveur. Un terme de recherche « sel & poivre » devient alors deux paramètres distincts.

Les accents passent par l'UTF-8

é n'est pas un caractère ASCII : il est d'abord codé en deux octets (0xC3 0xA9), puis chaque octet est échappé, ce qui donne %C3%A9. C'est pourquoi les URL accentuées semblent deux fois plus longues qu'attendu.

Espaces : %20 ou +

Dans un chemin d'URL, un espace doit être écrit %20. Dans une chaîne de requête de type formulaire, le + est une convention ancienne qui représente aussi un espace, et la plupart des serveurs l'acceptent.

Utiliser + dans un chemin produit une erreur : le serveur cherche un fichier dont le nom contient un signe plus. C'est la cause la plus fréquente des liens morts dans les URL construites à la main.

Le double encodage

Si vous encodez deux fois la même chaîne, % devient %25 et le résultat est illisible côté serveur : %C3%A9 devient %25C3%25A9. Ce symptôme indique presque toujours qu'un composant a été échappé par votre code puis de nouveau par un outil ou une bibliothèque.

Quand faut-il encoder une URL

Dès qu'une donnée utilisateur entre dans une URL : un terme de recherche, un nom de fichier, une adresse e-mail en paramètre. Sans encodage, un espace casse le lien, une esperluette coupe le paramètre, un dièse tronque tout ce qui suit.

Pour construire une URL en JavaScript, encodeURIComponent s'impose pour chaque valeur de paramètre, et l'API URLSearchParams gère l'ensemble sans risque d'oubli. L'encodage manuel à la main est une source d'erreur garantie dès qu'il y a plus de deux paramètres.
