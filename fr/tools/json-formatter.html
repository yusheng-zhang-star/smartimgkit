Formater et valider du JSON

1

Collez le JSON

Collez une réponse d'API, un fichier de configuration ou une charge utile (payload) mal indentée dans le champ d'entrée.

2

Choisissez l'indentation

2 espaces est la convention la plus répandue, 4 espaces se lit mieux sur un écran large. Pour un fichier destiné à un programme, utilisez la minification.

3

Validez si nécessaire

Le bouton de validation signale une erreur de syntaxe avec sa position. C'est ce qui distingue une virgule manquante d'une accolade fermée trop tôt.

4

Copiez le résultat

Le JSON formaté est replaçable dans votre éditeur. Si vous travaillez sous Git, le reformatage crée un diff ligne à ligne parfaitement lisible.

Les erreurs de JSON que tout le monde rencontre

Le JSON n'accepte pas les virgules finales : un dernier élément suivi d'une virgule provoque une erreur, même si JavaScript l'autorise dans un objet littéral. C'est l'erreur la plus fréquente, et la plus difficile à repérer à l'œil dans un fichier de mille lignes.

Les autres classiques : les clés doivent être entre guillemets doubles (les guillemets simples sont refusés), les commentaires sont interdits, et les valeurs NaN, Infinity ou undefined n'existent pas. Un JSON qui contient l'une de ces formes a été produit à la main, pas par un sérialiseur.

Les accents et les encodages

Le JSON est en UTF-8, les accents passent donc sans échappement. Si vous voyez des séquences \u00e9 à la place d'un é, c'est que la source a été sérialisée avec un échappement inutile : le résultat reste valide, mais illisible.

Indenter, minifier : quel intérêt réel

Indenter sert à lire et à comparer. Un JSON sur une seule ligne est illisible pour un humain et produit un diff inutilisable : la moindre modification réécrit toute la ligne. Indenté, chaque clé occupe sa propre ligne, et une revue de code devient possible.

Minifier sert à transmettre. Les espaces et retours à la ligne n'ont aucune signification en JSON : les supprimer réduit le poids de 20 à 40 % sur un fichier de configuration courant, ce qui compte pour une réponse d'API envoyée des millions de fois.

L'ordre des clés n'est pas garanti par la norme

La spécification JSON ne garantit pas l'ordre des clés. La plupart des implémentations le préservent, mais un outil de formatage qui retrie les clés alphabétiquement casse la comparaison avec la source. Vérifiez ce point avant d'utiliser un formateur en ligne sur un fichier versionné.

Avant de coller un JSON dans un outil en ligne

Un JSON contient souvent plus qu'on ne croit : jetons d'authentification, adresses e-mail, identifiants de clients, clés d'API. Coller une réponse d'API dans un service en ligne revient à transmettre ces données à un tiers, où elles peuvent rester dans des journaux.

Ici, le formatage se fait dans la page : rien ne part. Le corollaire est qu'il n'y a ni historique ni partage par lien. Si vous devez transmettre un JSON à un collègue, passez par un fichier, pas par un outil de formatage.
