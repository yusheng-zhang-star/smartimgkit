1. The Five-Tab Problem

You know the drill. You need a product photo prepped for Amazon. So you open tab #1 to resize to 1000×1000. Tab #2 to compress. Tab #3 to add a watermark. Tab #4 to strip the EXIF. Tab #5 to zip it all up. You drag, download, re-upload, drag, download, re-upload. Forty minutes later you've got one (1) image ready.

Multiply that by 30 products and you lose a day. Multiply by 300 products and you're shopping for a SaaS subscription you didn't want.

So here's the thing — I started building these workflows because I was running into the exact same wall. Same five tabs, same drag-and-drop loop, same "wait, did I run the watermark step on this one?" feeling. The fix wasn't another tool. It was chaining the tools together so the chain runs once and I move on.

Now? Upload 50 product photos, pick a preset, click one button, and 30 seconds later I'm downloading a ZIP. That's the pitch. The rest of this guide is the details.

2. What "Image Workflow" Actually Means

Single tools do one thing well. Compressor compresses. Watermark watermarks. Resizer resizes. That's the point — each tool is fast and focused.

But real image prep almost never involves one operation. It involves three to five. That's where workflows come in. A workflow is a pre-built chain of single tools, run in sequence, on every image you upload, with the result bundled into a single output.

Think of it like a recipe. A single tool is a single ingredient — flour, or sugar, or eggs. A workflow is the cake. You wouldn't open the flour bag, scoop, put it away, open the sugar bag, scoop, put it away, and call that "baking a cake." You do them in order, in the same bowl, and you get one finished thing at the end.

The other thing that makes workflows different: they run in your browser. Same as the single tools, nothing is uploaded to a server, nothing is logged, nothing requires a sign-in. The 50 product photos you prepped for Amazon never left your laptop. That's been a non-negotiable for us from day one.

How workflows stay free

Yeah, the question I get. "If it does this much, why is it free?" Two reasons. One, browser-side processing means we don't pay for servers to crunch your images — your CPU does. Two, the workflows reuse the same single-tool code, so there's no extra maintenance cost. It's the same engine doing more work in one trip. We're not running a charity — we're just not paying for the part that would have cost money.

4. Three Workflows Worth a Closer Look

I'll keep this short. Here are the three I personally run the most, with the actual use cases I've thrown at them.

Avatar Pipeline

The Avatar Pipeline runs four steps on every uploaded image: circle crop → apply a filter → add a watermark → resize to four preset dimensions. You end up with 4 sizes × N images in a single ZIP.

Why four sizes? Because Slack wants 200×200, Discord wants 128×128, Twitter wants 400×400, and your blog wants 80×80. Uploading a single 4000×4000 source means it gets downscaled weirdly on each platform. With the pipeline, you upload once and get the exact dimension each platform wants.

I've used it for onboarding a 12-person team. Twelve source photos in, 48 perfectly-sized outputs in a single ZIP, 20 seconds total. The watermark step is optional — leave the field blank and the step is skipped automatically.

E-Commerce Pack

For online stores. Pick a platform preset (Amazon 1000×1000, Shopify 2048×2048, eBay 1600×1600, Etsy 2000×2000, or custom), set your compression quality, optionally add a watermark, and run it. It handles up to 50 images per batch.

Honestly? The thing I appreciate most is that it stops me from accidentally uploading a 4000×4000 image to Shopify, which silently downscales it on the server side and wastes bandwidth on the visitor's first paint. Pre-resizing to 2048 means the image arrives at the size the page actually wants.

Compression tip: 75-85% is the sweet spot for product photos. Below 65% you'll see artifacts on smooth surfaces (white backgrounds, fabric, glass). Above 90% you're doubling file size for zero visible quality gain. The default is 82%, and I've never had a reason to change it.

Listing Image Suite

Same as E-Commerce Pack but runs the resize-watermark-compress chain four times in parallel — once for Amazon, once for Shopify, once for eBay, once for Etsy. One upload, four platform-specific ZIPs.

If you sell on multiple channels, this is the one that pays for itself in a week. Manually prepping the same product photo for four platforms means 4× the work, 4× the "did I get the dimensions right" anxiety, and 4× the chance of mixing up which version was for which store. The suite just generates all four and lets you download them in one go.

It's not glamorous. It doesn't use AI to add a "cinematic filter" to your soap bars. It just makes the boring prep work go away. That's the entire point of the workflows page.

6. Workflows vs. Single Tools: When Each Wins

Look, I'm not going to pretend workflows are always the right call. Sometimes one tool is enough.

Single tools win when:

  • You only need one operation (just compress, just resize, just watermark)
  • You're tweaking one image and need to see the result of each step before continuing
  • You want a different output for each image in the batch (mixed requirements)

Workflows win when:

  • You're prepping 10+ images for the same purpose
  • The chain of steps is always the same for every image
  • You want one ZIP at the end instead of 50 downloads
  • You don't want to remember which step to run on which image

Most of the time, the decision point is "more than ~10 images, same steps." Below that, single tools are faster. Above that, workflows save you from going crazy.

One last thing. Both — single tools and workflows — run entirely in your browser. No server, no upload, no sign-in, no account, no "free trial that converts to $19.99/month." Everything happens on your CPU. Close the tab and your images are gone, including any cached previews. That's by design, not a bug.

When NOT to use a workflow

If you have fewer than 5 images or each one needs different treatment, workflows will slow you down. Use single tools for one-offs and custom work. Workflows shine when the steps are identical across all images.

Also, if you're doing one-of-a-kind creative work where you want to see and tweak the result of each step, workflows move too fast. Nothing stops you from mixing — run the workflow, then hand-tweak the outputs. Your mileage may vary, but if you hit any of these, stop and reconsider.

7. FAQ

Do workflows cost extra?

No. Workflows are free, exactly like the single tools. Everything runs client-side, so there are no server costs to pass on.

Can I build my own custom workflow?

Custom workflows are on the roadmap. For now, all workflows are pre-built and maintained by the SmartImgKit team. If you have a specific chain in mind, drop a request on the workflows page.

How many images can I process at once?

Up to 50 per batch on the E-Commerce Pack and Listing Suite. The others vary — the Avatar Pipeline doesn't have a hard limit but performance scales with your CPU and RAM. 30-50 images is a comfortable upper bound for most laptops.

Are my images uploaded to a server?

No. Identical to the single tools — 100% client-side processing. Your images never leave your device. Open DevTools and watch the Network tab if you want proof. You won't see a single image upload.

Can I skip a step in a workflow?

Depends on the step. The watermark step in most workflows is optional — leave the text field empty and it skips. The compression and resize steps run by default. We're working on letting you toggle each step, but right now only the watermark has a built-in off switch.

What if my image is already the right size?

It still goes through the resize step, but the resize becomes a no-op. No quality loss, no size change, no extra processing time. It just continues down the chain.
