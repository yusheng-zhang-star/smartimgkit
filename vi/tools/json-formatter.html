🔧 Định dạng JSON

Định dạng đẹp, nén gọn và kiểm tra JSON hợp lệ ngay trong trình duyệt — paste vào là thấy kết quả.

Dán chuỗi JSON vào, chọn định dạng 2 hoặc 4 khoảng trắng, nén thành một dòng, hoặc kiểm tra tính hợp lệ. JSON được phân tích bằng JSON.parse gốc của trình duyệt nên hành xử đúng chuẩn — nếu sai, bạn nhận thông báo lỗi cụ thể ngay tại chỗ.

  • Bốn tác vụĐịnh dạng 2 khoảng trắng, định dạng 4 khoảng trắng, nén một dòng, kiểm tra hợp lệ
  • Công cụ lõiJSON.parse và JSON.stringify gốc của trình duyệt — đúng chuẩn ECMA-404
  • Kiểm tra lỗiJSON.parse trả thông báo lỗi của chính V8, chỉ ra vị trí cú pháp sai
  • Bảo mậtDữ liệu không rời khỏi tab trình duyệt của bạn

Cách dùng

1

Dán JSON

Dán chuỗi JSON — từ response API, file cấu hình hay log — vào ô JSON đầu vào. Nén hay đã định dạng đều được.

2

Chọn thao tác

Bấm "Định dạng" để xuống dòng thụt lề, "Nén gọn" để gộp một dòng, hoặc "Kiểm tra" để chỉ xác thực không sửa gì.

3

Đọc thông báo

Nếu JSON sai cú pháp, thông báo lỗi hiện ngay kèm lý do cụ thể — ví dụ Unexpected token — để bạn khoanh vùng chỗ sửa.

4

Lấy kết quả

Sao chép JSON đã xử lý về editor hoặc file cấu hình của bạn.

Từng thao tác giải thích rõ

Định dạng 2 hay 4 khoảng trắng — chọn theo chuẩn dự án

Cùng một dữ liệu nhưng hai "vẻ ngoài". Hai khoảng trắng là mặc định của JSON.stringify và là phổ biến nhất trong dự án JavaScript, Node.js. Bốn khoảng trắng gặp nhiều trong tài liệu và dự án Python. Nguyên tắc chọn: theo đúng file cấu hình sẵn có của dự án (kiểm tra .editorconfig hoặc file .js đang có), vì trộn hai kiểu thụt lề trong một repo là nguồn diff rác kinh điển khi cả nhóm cùng sửa file.

Nén gọn — khi nào dùng

Nén thành một dòng giúp giảm kích thước khi gửi JSON qua mạng hoặc nhúng vào biến môi trường. Lưu ý đây chỉ là gỡ khoảng trắng, không phải nén thực sự như gzip — với chuỗi lớn, gzip vẫn hiệu quả hơn nhiều. Dùng nén gọn khi cần dạng chữ "sạch" để dán vào chỗ chỉ nhận một dòng.

Kiểm tra hợp lệ và đọc thông báo lỗi

Nút kiểm tra chạy JSON.parse mà không ghi đè kết quả của bạn. Khi có lỗi, trình duyệt trả thông báo kiểu "Unexpected token } in JSON at position 42" — số 42 chính là vị trí ký tự trong chuỗi bạn đã dán (đếm từ 0). Mẹo: dán bản đã định dạng trước rồi mới kiểm tra, vì vị trí lỗi trên bản nhiều dòng gần với dòng thật hơn. Giới hạn cần biết: JSON.parse từ chối cả dấu phẩy thừa cuối mảng, comment //, và key không có ngoặc kép — cả ba đều hợp lệ trong JavaScript thuần nhưng sai chuẩn JSON.

Giới hạn dung lượng thực tế

Không có mức chặn cứng của công cụ, nhưng JSON.parse với chuỗi hàng chục MB có thể khiến tab trình duyệt chậm vài giây. Với file cấu hình, response API và dữ liệu dưới vài MB, mọi thao tác gần như tức thì.

Tình huống thực tế

Đọc response API của đối tác

Lập trình viên tích hợp cổng thanh toán hay API sàn TMĐT nhận về chuỗi JSON nén một dòng dài dằng dặc. Dán vào, định dạng 2 khoảng trắng là thấy ngay cấu trúc trường dữ liệu để viết parser.

Sửa file cấu hình an toàn

File package.json hay cấu hình CI bị chỉnh tay sai một dấu phẩy là cả pipeline sập. Dán qua "Kiểm tra" trước mỗi lần commit cấu hình — mất 3 giây, tiết kiệm cả buổi debug.

Dọn dữ liệu test

Cần mock dữ liệu cho bản demo: lấy JSON mẫu từ tài liệu API, định dạng lại cho đồng đội đọc được trong code review.
